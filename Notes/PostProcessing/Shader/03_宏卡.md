宏包括项目或包中通过 `#define` 定义的预处理宏，以及由 Shader Keyword、平台或渲染管线在编译期生成并参与条件编译的宏。

### 宏名：

`SAMPLE_TEXTURE2D_X_LOD`

**输入：**

```hlsl
SAMPLE_TEXTURE2D_X_LOD(textureName, samplerName, coord2, lod)
```

- `textureName`：要采样的纹理。
- `samplerName`：采样器状态。
- `coord2`：二维 UV 坐标。
- `lod`：指定采样的 Mip 层级。
- 编译条件：是否启用 XR 纹理数组。

**输出 / 结果：**

返回指定 UV 与 Mip 层采样到的纹理颜色。普通非 XR 模式下展开为：

```hlsl
SAMPLE_TEXTURE2D_LOD(textureName, samplerName, coord2, lod)
```

XR 纹理数组模式下展开为：

```hlsl
SAMPLE_TEXTURE2D_ARRAY_LOD(
    textureName,
    samplerName,
    coord2,
    SLICE_ARRAY_INDEX,
    lod
)
```

**职责：**

封装 URP 中指定 Mip 层的屏幕纹理采样，并在 XR 模式下自动选择当前眼睛对应的纹理数组层。

**所在模块：**

```hlsl
#include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"
```

**常见搭配：**

- `TEXTURE2D_X` 或 `TEXTURE2D_X_FLOAT`
- `UNITY_SETUP_STEREO_EYE_INDEX_POST_VERTEX(input)`
- `_BlitTexture`
- `_BlitMipLevel`
- `sampler_LinearClamp`

**坑点：**

- `_X` 表示支持普通二维纹理和 XR 纹理数组，不表示 X 轴方向。
- `_LOD` 负责指定 Mip 层，不负责线性过滤；过滤方式由 `samplerName` 决定。
- XR 模式下应先正确设置当前眼睛索引，否则可能采样错误的纹理数组层。

### 宏名：

`TEXTURE2D`

**输入：**

```hlsl
TEXTURE2D(textureName)
```

- `textureName`：要声明的纹理对象名称。

**输出 / 结果：**

在 HLSL 中声明一个二维纹理对象，在不同图形 API 下展开为对应的纹理声明语法（如 `Texture2D textureName`）。

**职责：**

以跨平台方式声明二维纹理对象，使同一份 Shader 代码可在 DX11/DX12/Vulkan/Metal/OpenGL 上编译。

**所在模块：**

```hlsl
#include "Packages/com.unity.render-pipelines.core/ShaderLibrary/API/..." (平台相关)
```

通过 `Core.hlsl` 间接包含。

**常见搭配：**

- `SAMPLER(sampler_textureName)` 或使用已有的 `sampler_LinearClamp`
- `SAMPLE_TEXTURE2D(textureName, samplerName, uv)`
- `SAMPLE_TEXTURE2D_X_LOD(textureName, samplerName, uv, lod)`

**坑点：**

- `TEXTURE2D` 只是声明纹理对象，不包含采样器；采样时需要单独声明或使用全局采样器。
- `TEXTURE2D(_BloomTex)` 声明在 `HLSLINCLUDE` 中时，位置应在 `#include` 之后、`CBUFFER` 之前或之后均可，但惯例是放在 include 之后、CBUFFER 之前。
- 不要把纹理声明放在 `CBUFFER_START / CBUFFER_END` 内部，否则会报错。

### 宏名：

`SAMPLER`

**输入：**

```hlsl
SAMPLER(samplerName)
```

- `samplerName`：要声明的采样器状态名称。

**输出 / 结果：**

在 HLSL 中声明一个采样器状态对象，在不同图形 API 下展开为对应的采样器声明。

**职责：**

以跨平台方式声明纹理采样器状态，控制纹理的过滤模式（如线性/点采样）和寻址模式（如 Clamp/Wrap）。

**所在模块：**

```hlsl
#include "Packages/com.unity.render-pipelines.core/ShaderLibrary/API/..." (平台相关)
```

通过 `Core.hlsl` 间接包含。

**常见搭配：**

- `TEXTURE2D(textureName)`
- `SAMPLE_TEXTURE2D(textureName, samplerName, uv)`
- 可以复用全局采样器如 `sampler_LinearClamp` 而不单独声明

**坑点：**

- 声明了 `SAMPLER(sampler_BloomTex)` 但实际采样时使用 `sampler_LinearClamp`（Blit.hlsl 提供的全局采样器）是合法的，但未使用的采样器声明是多余的。
- 采样器名称必须与 `SAMPLE_TEXTURE2D` 中使用的采样器名称一致，否则采样会使用错误的过滤/寻址模式。

### 宏名：

`CBUFFER_START`

**输入：**

```hlsl
CBUFFER_START(bufferName)
```

- `bufferName`：常量缓冲区的名称，在 URP 中传递材质属性时习惯固定为 `UnityPerMaterial`。

**输出 / 结果：**

在 D3D11/D3D12/Vulkan 等支持原生常量缓冲区的 API 下展开为：
```hlsl
cbuffer bufferName {
```
在其他平台（如 Metal/OpenGL）下展开为各平台对应的 Shader 常量块声明语法，保证跨平台编译。

**职责：**

屏蔽底层不同图形 API 对常量缓冲区声明方式的差异，保证常量缓冲区的跨平台兼容性。

**所在模块：**

`Packages/com.unity.render-pipelines.core/ShaderLibrary/API/Common.hlsl`（通过 `Core.hlsl` 自动引入）

**常见搭配：**

- `CBUFFER_END`
- `UnityPerMaterial`

**坑点：**

- 必须且只能搭配 `CBUFFER_END` 闭合使用，缺一不可，否则会导致编译语法报错。
- 常量缓冲区内仅能放入普通标量、向量或矩阵，严禁在其中声明纹理（`TEXTURE2D`）或采样器（`SAMPLER`）。
