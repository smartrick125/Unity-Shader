# 02_非函数卡

本文件只用于保存具体的 C# 字段、属性、常量、枚举、结构体、事件、委托、特性、序列化配置、资源句柄及其他非函数对象记录，不定义模板。

新增记录前必须读取并使用 `.codex-rules/03_C#知识总结规范.md` 中的“非函数卡固定模板”。只有用户主动提出记录某个 C# 非函数对象时，才在本文件末尾追加记录。

## 非函数记录

### 名字：

`RenderPassEvent`

**类型：**

URP Pass 插入时机枚举

**作用：**

决定 `ScriptableRenderPass` 在 URP 渲染流程中的执行位置。

**所在层级：**

URP Renderer / ScriptableRenderPass

**参与的数据流：**

```text
Renderer Feature 设置 renderPassEvent
↓
URP 根据该事件排序 Pass
↓
Pass 在指定阶段执行
```

**常见坑：**

- **时机太早导致透明物体丢失**：如将 Bloom 放在 `AfterRenderingSkybox`，此时透明物体（水面、玻璃、粒子特效、半透明火焰）**尚未绘制**。执行 Bloom 时无法捕获这些透明高光，且随后绘制的透明物体还会直接盖在光晕之上，破坏画面层级。
- **推荐时机**：通用场景后处理应放在 `RenderPassEvent.BeforeRenderingPostProcessing`，此时不透明物体、天空盒、透明物体均已渲染完毕，能抓取到完整的全场景图像。
- 插太晚可能已经做完 URP 内置后处理（如色调映射 Tonemapping），导致颜色空间和曝光不匹配。
- 需要深度/法线等 GBuffer/Prepass 贴图时，要确认对应纹理生成的事件节点早于当前 Pass。


### 名字：

`renderingData.cameraData.cameraType` 与 `CameraType.Game`

**类型：**

`cameraType` 是当前相机数据中的 `CameraType` 枚举值；`CameraType.Game` 是该枚举中表示普通游戏渲染相机的成员。

**作用：**

描述当前正在由 URP 处理的相机类型，可用于决定某个 Renderer Feature 是否要为这台相机注入自定义 RenderPass。

**所在层级：**

Unity 相机类型 / URP `RenderingData → CameraData` / `ScriptableRendererFeature.AddRenderPasses()`。

**参与的数据流：**

```text
URP 为当前相机准备 RenderingData
↓
读取 cameraData.cameraType
↓
与 CameraType.Game 比较
↓
匹配时调用 EnqueuePass()，否则跳过该相机
```

**常见坑：**

- `CameraType.Game` 判断的是相机类型，不是相机是否带有 `MainCamera` 标签；多个运行时游戏相机都可能匹配。
- 它也不等于 `Application.isPlaying`：编辑器处于非播放状态时可能存在 Game 类型相机，播放状态下也可能处理 SceneView、Preview 或 Reflection 等其他类型相机。
- 该筛选只决定是否入队，不会直接执行 RenderPass、Shader 或 RenderGraph 节点。

### 名字：

`AccessFlags.ReadWrite`

**类型：**

Render Graph 纹理访问权限枚举值。

**作用：**

声明 RasterRenderPass 对渲染目标同时需要读取和写入。在使用 `Blend One One` 等混合模式时，GPU 需要先读取渲染目标已有颜色再与新输出混合，因此必须使用 `ReadWrite` 而非 `Write`。

**所在层级：**

`UnityEngine.Rendering.RenderGraphModule` / `AccessFlags` 枚举 / 用于 `builder.SetRenderAttachment()` 的第三个参数。

**参与的数据流：**

```text
builder.SetRenderAttachment(dst, 0, AccessFlags.ReadWrite)
↓
Render Graph 标记该纹理需要 Load（加载已有颜色）
↓
GPU 混合阶段读取已有颜色 + 新输出颜色完成 Blend
```

**常见坑：**

- **“谁在读哪张图”的混淆**：`builder.UseTexture(passData.src, AccessFlags.Read)` 是让 **Shader 片元着色器** 采样输入贴图（如 `tempA`）；而 `builder.SetRenderAttachment(passData.dst, 0, AccessFlags.ReadWrite)` 是让 **GPU 硬件混合单元** 先将渲染目标（如 `srcCamColor` 原图）加载进显存，再与 Shader 输出的新颜色相加写回。二者操作的是不同贴图、不同硬件阶段的读！
- 使用 `AccessFlags.Write` 时，Render Graph 会判定不需要保留底图（LoadAction = DontCare），导致 `Blend One One` 变成 `bloom + 0 = bloom`，原场景颜色直接丢失。
- 只有使用了硬件混合模式或需要保留目标已有内容的 Pass 才需要 `ReadWrite`；普通全屏覆盖写入使用 `Write` 即可。


### 名字：

`isActiveTargetBackBuffer`

**类型：**

`UniversalResourceData` 的 `bool` 属性。

**作用：**

判断当前相机是否直接渲染到后缓冲（BackBuffer）。如果为 `true`，说明没有中间 RT 可以读写，自定义后处理 Pass 应提前返回以避免无效操作。

**所在层级：**

`UnityEngine.Rendering.Universal` / `UniversalResourceData` / 通常在 `RecordRenderGraph()` 开头检查。

**参与的数据流：**

```text
URP 配置相机渲染路径
↓
resourceData.isActiveTargetBackBuffer 反映是否有中间 RT
↓
为 true 时跳过自定义后处理，避免在 BackBuffer 上无效操作
```

### 名字：

`msaaSamples`

**类型：**

`RenderTextureDescriptor` 的 `int` 字段

**作用：**

指定渲染目标纹理的多重采样抗锯齿（MSAA）采样数。在后处理临时纹理中，我们通常显式将其设为 `1`（即关闭抗锯齿），以避免复制相机属性时误继承开启的 MSAA，造成严重的显存和带宽消耗，同时防止 Shader 在普通采样时因多重采样格式而报错。

**所在层级：**

`UnityEngine.RenderTextureDescriptor` / 用于创建 Render Graph 临时纹理时配置的参数。

**参与的数据流：**

```text
从 cameraTargetDescriptor 复制属性包
↓
msaaSamples = 1 (强制设为 1，关闭多重采样)
↓
CreateRenderGraphTexture 根据此配置生成非 MSAA 临时纹理
```

**常见坑：**

- 若直接拷贝相机参数 `cameraTargetDescriptor` 而不将 `msaaSamples` 改为 `1`，当游戏开启了全局抗锯齿时，临时纹理也会变成 MSAA 纹理。这会导致普通 Shader 采样的 UV 映射失效或编译报错，并造成数倍的渲染性能下降。
- 它只能表示采样次数（如 1、2、4、8），不可写入其他任意数值。

### 名字：

`PassData`

**类型：**

自定义 `class`（当前 Core SRP 17.3 的 `AddRasterRenderPass<PassData>()` 要求满足 `where PassData : class, new()`，常在自定义 `ScriptableRenderPass` 类内部作为私有嵌套类声明）。

**作用：**

作为数据载体包裹资源句柄（如 `TextureHandle`）和执行参数（如 `Material`），打通 RenderPass 的“录制阶段（Record）”与“执行阶段（Execute）”之间的数据流动。把 `activeColorTexture` 赋给 `copySourceTexture` 时只复制句柄值，两个字段仍引用同一个 Render Graph 纹理资源。

**所在层级：**

在 `ScriptableRenderPass` 的子类中声明，并作为泛型参数传入 `AddRasterRenderPass<PassData>`。

**参与的数据流：**

```text
AddRasterRenderPass<PassData>(..., out passData) 创建节点与 PassData 实例
↓
Record 阶段把资源句柄写入字段（如 passData.copySourceTexture = resourceData.activeColorTexture）
↓
Render Graph 在 Execute 阶段通过回调参数 (PassData data, ...) 把同一节点的数据交给执行方法
↓
执行方法使用 data.copySourceTexture 访问原来的相机颜色资源
```

**常见坑：**

- 在 `RecordRenderGraph` 内，除 `PassData` 外，绝不能直接在执行 Lambda 内部捕获其他的局部变量或类成员，否则会因为“闭包捕获”产生不必要的 GC Alloc 并破坏线程安全性。所有要在 `SetRenderFunc` 内部使用的数据都**必须**声明为 `PassData` 的成员并进行传参。
- `PassData` 的生命周期由 RenderGraph 系统托管，应该只存放资源句柄和渲染参数拷贝，不能在执行阶段去修改它的字段传回主线程。
- `passData.copySourceTexture = resourceData.activeColorTexture` 不是再次创建、获取或复制相机颜色纹理；这是标准的结构体字段赋值，只把轻量 `TextureHandle` 号码牌传到执行阶段。
