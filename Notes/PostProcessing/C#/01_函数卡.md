# 01_函数卡

本文件只用于保存具体的 C# 方法、构造函数、Unity 生命周期方法、回调、协程、异步方法和本地函数记录，不定义模板。

新增记录前必须读取并使用 `.codex-rules/03_C#知识总结规范.md` 中的“函数卡固定模板”。只有用户主动提出记录某个 C# 函数或方法时，才在本文件末尾追加记录。

## 函数记录

### 函数名：

`ScriptableRendererFeature.Create()`

**输入：**

无显式参数；读取 Renderer Feature 自身的序列化字段、Shader 引用与设置数据（如 `BloomSettings`）。

**输出：**

无返回值；创建并缓存该 Feature 所需的持久化对象（如 `Material`、`ScriptableRenderPass` 实例）。

**职责：**

负责 Renderer Feature 的初始化工作，实例化 Material 与 RenderPass 并配置静态参数（如 `renderPassEvent`）。

**所在模块：**

`UnityEngine.Rendering.Universal.ScriptableRendererFeature` / 初始化与配置更新阶段。

**是否深挖：**

现阶段需要掌握：
- 它是在 Renderer Feature **首次加载初始化**、**在 Inspector 中修改参数**、或者**脚本重新编译**时由 Unity 引擎触发调用。
- 它与渲染阶段的不透明/透明切换完全无关，更**不是每帧调用的函数**。
- 暂时不用深挖 URP 底层何时触发 Feature 垃圾回收与重建的全部底层生命周期。

### 函数名：

`TextureHandle.IsValid()`

**输入：**

无显式参数，读取当前 `TextureHandle` 内部保存的 RenderGraph 资源句柄状态。

**输出：**

返回 `bool`：句柄能够引用当前 RenderGraph 中已注册的纹理资源时返回 `true`；句柄为空、未初始化或已经无效时返回 `false`。该方法不检查纹理内容、尺寸、Shader、Material 或渲染结果是否正确。

**职责：**

判断当前 `TextureHandle` 是否可以作为合法的 RenderGraph 纹理资源引用，避免把无效句柄继续传给 Blit 或其他 RenderGraph Pass。

**所在模块：**

Unity 6000.3.9f1 / Core Render Pipeline 17.3.0 / Runtime RenderGraph；当前用于 `Assets/Scripts/UnityShaderBook/Chapter12/GaussianBlur/GaussianBlur_RenderPass.cs` 的纹理句柄检查。

**是否深挖：**

现阶段需要掌握：它检查的是资源句柄是否合法，常与 `!handle.IsValid()` 和提前 `return` 配合；它不等于检查纹理已经写入有效画面，也不能保证句柄可以跨 RenderGraph 执行或跨帧继续使用。暂时不用深挖内部 `ResourceHandle` 的索引、版本号和资源注册表实现。

### 函数名：

`ScriptableRenderer.EnqueuePass(ScriptableRenderPass pass)`

**输入：**

`pass`：本次要加入当前相机渲染队列的 `ScriptableRenderPass` 实例，例如 `gaussianRenderPass`。

**输出：**

无返回值；把传入的 RenderPass 添加到当前 `ScriptableRenderer` 的活动 RenderPass 队列，等待 URP 后续按 `renderPassEvent` 安排处理。

**职责：**

把一个自定义 `ScriptableRenderPass` 注入当前相机本帧的渲染流程；调用本身只是入队，不会立即运行 Shader 或产生画面结果。

**所在模块：**

Unity 6000.3.9f1 / URP 17.3.0 / `ScriptableRenderer` 调度层；当前用于 `Assets/Scripts/UnityShaderBook/Chapter12/GaussianBlur/GaussianBlur_RendererFeature.cs` 的 `AddRenderPasses()`。

**是否深挖：**

现阶段需要掌握：`EnqueuePass()` 加入的是一个 `ScriptableRenderPass`，之后这个 Pass 的 `RecordRenderGraph()` 可以登记一个或多个 RenderGraph 节点；入队数量与 RenderGraph 节点数量不是同一个概念。暂时不用深挖活动队列的内部排序实现和兼容模式分支。

### 函数名：

`VolumeManager.instance.stack.GetComponent<T>()`

**输入：**

泛型类型参数 `T`：必须是 `VolumeComponent` 的子类，如 `Bloom_CustomValumeComponent`。

**输出：**

返回当前帧所有活跃 Volume 按权重混合后的 `T` 类型实例。如果场景中没有包含该组件的 Volume，返回的实例所有参数都保持默认值（`overrideState = false`）。

**职责：**

从 Volume 混合堆栈中获取指定类型的后处理参数组件，供 RenderPass 读取并传递给 Material。

**所在模块：**

`UnityEngine.Rendering` / Volume System / 通常在 `ScriptableRenderPass` 的 `UpdateSettings()` 或 `RecordRenderGraph()` 中调用。

**是否深挖：**

现阶段需要掌握：返回的组件不为 null（Volume 系统总会返回默认实例），但 `overrideState` 为 false 时应使用 RendererFeature 提供的 defaultSettings 回退值。暂时不用深挖 VolumeStack 内部的混合实现。

### 函数名：

`Blitter.BlitTexture(RasterCommandBuffer cmd, TextureHandle source, Vector4 scaleBias, Material material, int passIndex)`

**输入：**

- `cmd`：当前 RasterGraphContext 的命令缓冲。
- `source`：要作为 `_BlitTexture` 采样的源纹理句柄。
- `scaleBias`：UV 缩放和偏移，通常为 `new Vector4(1,1,0,0)` 表示全屏无偏移。
- `material`：执行 Blit 的 Shader 材质。
- `passIndex`：要执行的 Shader Pass 索引。

**输出：**

无返回值；向命令缓冲写入绘制指令，将源纹理通过指定 Material 和 Pass 渲染到当前 `SetRenderAttachment` 设置的渲染目标上。

**职责：**

在 RenderGraph 的 RasterRenderPass 中，使用指定 Material 的指定 Pass 将源纹理 Blit 到目标纹理。内部会自动设置 `_BlitTexture` 全局纹理。

**所在模块：**

Unity 6000.3.9f1 / Core Render Pipeline 17.3.0 / `Blitter` 静态类 / 通常在 `SetRenderFunc` 的 lambda 中调用。

**是否深挖：**

现阶段需要掌握：它会自动把 `source` 绑定为 `_BlitTexture`，Shader 中通过 `SAMPLE_TEXTURE2D_X_LOD(_BlitTexture, ...)` 采样；`passIndex` 对应 Shader 中 Pass 的声明顺序（从 0 开始）。暂时不用深挖 Blitter 内部如何调用全屏三角形绘制。

### 函数名：

`Shader.PropertyToID(string name)`

**输入：**

`name`：Shader 属性名称字符串，如 `"_BlurSpread"`。

**输出：**

返回 `int`：该属性名称对应的全局唯一整数 ID，用于后续的 `material.SetFloat()` 等调用。

**职责：**

将 Shader 属性名称转换为高效的整数 ID，避免每次通过字符串查找属性带来的性能开销。

**所在模块：**

UnityEngine / Shader / 通常在 `ScriptableRenderPass` 的静态字段初始化中调用一次并缓存。

**是否深挖：**

现阶段需要掌握：ID 字符串必须与 Shader Properties 或 CBUFFER 中声明的变量名大小写完全一致，否则 `SetFloat` 不会报错但值也不会生效。暂时不用深挖 Unity 内部的属性 ID 映射表实现。

### 函数名：

`RecordRenderGraph(RenderGraph renderGraph, ContextContainer frameData)`

**输入：**

- `renderGraph`：用来创建临时纹理与向渲染图系统注册 Pass 的 RenderGraph 实例。
- `frameData`：保存了当前帧全部上下文数据（包括相机参数、颜色贴图等）的数据包。

**输出：**

无返回值；执行该函数后，会向 URP 渲染图系统录入具体的资源声明和绘制任务（Blit / Draw Call）。

**职责：**

在主线程上执行，负责两件事：
1. 从 Volume 数据中心获取动态参数并传递给 `Material`。
2. 声明 Pass 运行所需的输入、输出临时纹理（如调用 `AddRasterRenderPass` 并设置 `UseTexture` 和 `SetRenderAttachment`），并将具体的渲染工作包装为 `SetRenderFunc` 的执行回调。

**所在模块：**

`ScriptableRenderPass` 基类虚方法 / 每一帧主线程渲染录制阶段。

**是否深挖：**

现阶段需要掌握：
- 它在主线程立刻跑完，内部任何与 `context.cmd` 相关的 GPU 指令都只是被**注册**，并没有被**执行**。
- 它在每一帧都需要为活动的 Game 相机重新运行一次，因此不应在内部做耗时的频繁内存分配操作。

暂时不用深挖：
- URP 内部渲染图（Render Graph）的分析拓扑排序和多线程合并优化的具体算法。

### 函数名：

`ScriptableRendererFeature.AddRenderPasses(ScriptableRenderer renderer, ref RenderingData renderingData)`

**输入：**

- `renderer`：当前相机正在使用的 `ScriptableRenderer` 实例。
- `renderingData`：当前相机与渲染管线相关的实时状态数据（如 `renderingData.cameraData.cameraType`）。

**输出：**

无返回值；通过在函数体内调用 `renderer.EnqueuePass(pass)`，将需要执行的 Pass 注入到渲染队列中。

**职责：**

URP 的每帧调度回调。每帧针对每个活动相机被引擎调用，负责根据当前相机的属性（如是否为 `CameraType.Game`）决定是否把 Pass 举手加入本帧的渲染流水线。

**所在模块：**

`UnityEngine.Rendering.Universal.ScriptableRendererFeature` / 每帧每相机调度阶段。

**是否深挖：**

现阶段需要掌握：
- **它是每帧、每个相机都会调用的**，与一次性初始化的 `Create()` 形成鲜明对比。
- 它自身不执行具体 Shader，它的唯一职责是决定“当前这台相机本帧要不要跑这个 Pass”并通过 `renderer.EnqueuePass()` 报名。
- 暂时不用深挖 URP 如何将多个 RendererFeature 按照注入顺序合并到渲染流水线的内部源码。

### 函数名：

`IRasterRenderGraphBuilder.SetRenderAttachment(TextureHandle texture, int index, AccessFlags accessFlags)`

**输入：**

- `TextureHandle texture`：本次要绑定作为渲染输出目标的纹理句柄。
- `int index`：渲染目标槽位索引（Color Attachment Index，通常为 `0`，对应 Shader 里的 `SV_Target0`）。
- `AccessFlags accessFlags`：对该渲染目标的访问权限声明（如 `AccessFlags.Write` 或 `AccessFlags.ReadWrite`）。

**输出：**

无返回值；向 Render Graph 构建器声明该 Raster Pass 关联的 Framebuffer 颜色输出槽位。

**职责：**

将指定的纹理句柄挂接到渲染流水线的 MRT（多渲染目标）指定槽位上，作为当前 Pass 的颜色写入目标。

**所在模块：**

`UnityEngine.Rendering.RenderGraphModule.IRasterRenderGraphBuilder` / 渲染图节点资源声明阶段。

**是否深挖：**

现阶段需要掌握：
- **参数 `0` 的含义**：代表第 0 号颜色输出槽位，在 HLSL Shader 片元着色器中对应 `SV_Target0`（普通单贴图 Blit 固定使用 `0`；只有多渲染目标 MRT 时才会用到 `1`、`2` 等）。
- **参数 `accessFlags` 的影响**：纯覆盖写入用 `AccessFlags.Write`；如果使用了 `Blend One One` 等需要保留目标已有画面做混合的操作，必须声明为 `AccessFlags.ReadWrite`，否则 Render Graph 会将其判定为不需要加载旧数据（LoadAction = DontCare），导致混合底图丢失。
- 暂时不用深挖底层 Framebuffer Attachment 与移动端 Tile-based 内存绑定的具体实现。
