# 00_类卡

本文件只用于保存具体的 C# 类及 Unity 组件类记录，不定义模板。

新增记录前必须读取并使用 `.codex-rules/03_C#知识总结规范.md` 中的“类卡固定模板”。只有用户主动提出记录某个 C# 类时，才在本文件末尾追加记录。

## 类记录

### 类名：

`ScriptableRenderPass`

**类型：**

URP 自定义渲染通道基类 / 渲染流程步骤类

**一句话职责：**

表示 URP 渲染流程中可以被插入执行的一步自定义渲染操作。

**所在模块：**

URP Renderer / Scriptable Render Pipeline / RenderGraph

**它管理什么数据：**

- `renderPassEvent`
- `Material`
- Shader 参数
- 临时纹理句柄
- Pass 名称
- 当前效果需要的配置

**它被谁创建：**

通常由 `ScriptableRendererFeature` 在 `Create()` 中创建。

也可以由普通脚本创建后通过 `renderer.EnqueuePass` 注入。

**它被谁调用：**

URP Renderer 在每帧构建渲染流程后调用。

Unity 6 RenderGraph 路径中主要调用 `RecordRenderGraph()`。

**关键方法：**

#### `RecordRenderGraph(renderGraph, frameData)`

**职责：**

在 RenderGraph 中注册这个 Pass 的资源读写和执行逻辑。

**什么时候调用：**

URP 每帧、每个相关相机渲染时调用。

#### `Execute(context, renderingData)`

**职责：**

旧兼容路径中执行渲染命令。

**什么时候调用：**

非 RenderGraph / Compatibility Mode 路径中使用。

**输入：**

- `frameData`：当前帧上下文数据包。
- `renderGraph`：用来添加 Pass、创建临时纹理、声明资源读写。
- Camera Color / Depth：当前相机颜色图、深度图等资源。
- `Material` / Shader：具体屏幕处理算法。

**输出 / 影响：**

- 向 RenderGraph 注册一次或多次渲染操作。
- 可能修改 Camera Color。
- 可能生成临时 RenderTexture。
- 可能写入全局纹理。

**和其他类的关系：**

- `ScriptableRendererFeature`：通常负责创建并 enqueue 它。
- `RenderGraph`：它通过 RenderGraph 注册实际渲染步骤。
- `TextureHandle`：它用 TextureHandle 表示读写的纹理资源。
- `Material` / Shader：它调用材质和 Shader 完成像素处理。

**是否需要深挖：**

现阶段重点掌握：

- 它是“真正执行渲染逻辑的 Pass 类”。
- 它读什么、写什么、插在哪里。

暂时不用深挖 URP 内部如何调度所有 Pass。

### 类名：

`CoreUtils`

**类型：**

`UnityEngine.Rendering` 命名空间中的 `public static class`，是 Core Scriptable Render Pipeline 提供的静态工具类，不能通过 `new CoreUtils()` 创建实例。

**一句话职责：**

集中提供 SRP 常用的材质创建、Unity 对象销毁、渲染目标设置和通用资源处理工具。

**所在模块：**

Unity 6000.3.9f1 / Core Render Pipeline 17.3.0 / `Runtime/Utilities/CoreUtils.cs`

**它管理什么数据：**

- SRP 共用的默认纹理、立方体纹理和体积纹理等静态资源。
- Cubemap 面朝向、菜单区段与优先级等静态数据。
- 多种渲染工具方法所需的公共状态和缓存资源。

**它被谁创建：**

`CoreUtils` 是静态类，不会被业务代码实例化；第一次访问其静态成员时，由 C# 运行时负责静态类型初始化。在 Unity Editor 中，其静态构造函数还会注册程序集重载前的资源清理逻辑。

**它被谁调用：**

由 URP、HDRP、Core SRP 内部代码以及自定义 `ScriptableRendererFeature`、`ScriptableRenderPass` 等渲染脚本通过类名直接调用。

**关键方法：**

#### `CreateEngineMaterial(Shader shader)`

**职责：**

根据传入的 `Shader` 创建供渲染管线内部或自定义渲染功能使用的 `Material`。

**什么时候调用：**

通常在 `ScriptableRendererFeature.Create()` 等初始化阶段创建并缓存材质时调用，不应在每帧渲染路径中无理由重复创建。

#### `Destroy(UnityEngine.Object obj)`

**职责：**

根据当前处于编辑模式还是运行模式，选择合适的 Unity 对象销毁方式。

**什么时候调用：**

材质或其他 Unity 资源不再使用、Renderer Feature 被重新创建或执行 `Dispose()` 清理时调用。

**输入：**

- `Shader shader`：`CreateEngineMaterial()` 用来创建材质的 Shader；为 `null` 时无法创建有效材质。
- `UnityEngine.Object obj`：`Destroy()` 要销毁的 Unity 对象，例如之前创建的 `Material`。

**输出 / 影响：**

- `CreateEngineMaterial()` 返回新创建的 `Material`，失败时可能返回 `null` 并输出错误。
- `Destroy()` 没有返回值，会销毁目标 Unity 对象；编辑模式与运行模式下采用的具体销毁方式不同。

**和其他类的关系：**

- `Shader`：作为创建引擎材质时的输入。
- `Material`：由 `CreateEngineMaterial()` 创建，并可由 `Destroy()` 清理。
- `ScriptableRendererFeature`：通常在 `Create()` 和 `Dispose()` 中调用相关工具方法。
- `UnityEngine.Object`：`Destroy()` 接收的基础对象类型。

**是否需要深挖：**

现阶段重点掌握：

- `CoreUtils` 是静态工具类，使用 `CoreUtils.MethodName()` 调用，不创建实例。
- 创建的 `Material` 应缓存复用，并在不再使用时通过 `CoreUtils.Destroy()` 清理。
- 使用前需要引入 `using UnityEngine.Rendering;`。

暂时不用深挖：

- `CoreUtils` 内部所有渲染目标重载、默认纹理缓存和编辑器程序集重载清理的具体实现。

### 类名：

`VolumeComponent`

**类型：**

URP/HDRP 后处理 Volume 系统的参数组件基类。

**一句话职责：**

表示一个可以挂载到 Volume 上的后处理参数集合，运行时通过 `VolumeManager` 按权重混合后提供给 RenderPass 读取。

**所在模块：**

Unity Rendering / Volume System / `UnityEngine.Rendering`

**它管理什么数据：**

- 一组 `VolumeParameter`（如 `ClampedIntParameter`、`ClampedFloatParameter`），每个参数有 `value` 和 `overrideState`。

**它被谁创建：**

由用户在 Volume Profile 中添加，Volume 系统在运行时自动实例化和管理。

**它被谁调用：**

在 `ScriptableRenderPass` 的 `RecordRenderGraph()` 或 `Execute()` 中，通过 `VolumeManager.instance.stack.GetComponent<T>()` 读取当前生效的参数值。

**关键方法：**

无需手动调用关键方法；主要通过 Volume 系统自动混合参数，RenderPass 端只需读取 `.value` 和 `.overrideState`。

**输入：**

- Volume Profile 中配置的参数值和 override 状态。
- Volume 的权重、优先级和触发范围（Global / Local）。

**输出 / 影响：**

- 通过 `VolumeManager.instance.stack.GetComponent<T>()` 返回当前帧混合后的参数实例。
- RenderPass 读取参数值后设置到 Material 上，影响 Shader 行为。

**和其他类的关系：**

- `VolumeManager`：管理所有 Volume 的混合堆栈。
- `Volume`：场景中的 Volume 游戏对象，持有 VolumeProfile。
- `ScriptableRenderPass`：读取 VolumeComponent 参数并传递给 Material/Shader。

**是否需要深挖：**

现阶段重点掌握：

- 如何继承 `VolumeComponent` 定义自定义后处理参数。
- 如何通过 `VolumeManager.instance.stack.GetComponent<T>()` 读取参数。
- `overrideState` 为 `true` 时使用 Volume 值，否则回退到默认值。

暂时不用深挖：

- VolumeManager 内部的权重混合和空间插值算法。

### 类名：

`ScriptableRendererFeature`

**类型：**

URP 自定义渲染特征基类 / 渲染管线扩展管理器

**一句话职责：**

作为扩展 URP 渲染功能的入口，负责声明、初始化自定义的 RenderPass 实例，并控制其何时注入到 URP 渲染器中。

**所在模块：**

`UnityEngine.Rendering.Universal` / URP Pipeline Feature Layer

**它管理什么数据：**

- `Material`：后处理需要执行的渲染材质实例的生命周期。
- 自定义配置数据（如 `GaussianBlurSettings`）。
- 自定义 `ScriptableRenderPass` 的生命周期实例（创建与配置）。

**它被谁创建：**

由 URP 渲染器资源（`UniversalRendererData`）通过反序列化配置列表自动创建，并在项目启动、Domain Reload 或 Feature 启用时实例化。

**It被谁调用：**

- 初始化调用：`Create()`。
- 逐帧调用：`AddRenderPasses()`（在主线程渲染准备阶段）。
- 销毁调用：`Dispose()`（特征被禁用或重建时）。

**关键方法：**

#### `Create()`

**职责：**

执行材质初始化、分配自定义配置数据以及实例化需要用到的 `ScriptableRenderPass`。

**什么时候调用：**

特征被创建、材质重置、脚本重载（Domain Reload）或面板配置修改时调用。

#### `AddRenderPasses(renderer, renderingData)`

**职责：**

在逐帧渲染时，将初始化好的自定义 Pass 挂载并注入当前相机的渲染队列中。

**什么时候调用：**

每一帧主线程的渲染准备阶段中，为每一个需要渲染的活动相机依次调用。

**和其他类的关系：**

- `UniversalRendererData`：持有它的配置列表。
- `ScriptableRenderPass`：由它创建、持有并负责在每帧 Enqueue 到渲染器。
- `CoreUtils`：用于在 `Create()` 中安全创建材质，在销毁时安全释放材质资源。

**是否需要深挖：**

现阶段重点掌握：

- 它是一个“大管家/扩展入口”，负责生命周期（创建、入队和销毁）。
- 绝不要在它的 `Create()` 或 `AddRenderPasses()` 内部编写具体的 Blit 或 Draw 指令。

暂时不用深挖：

- URP 内部序列化及底层是如何加载并对 Renderer Features 进行反射调用的。

### 类名：

`PassData`（自定义嵌套类 / 结构体）

**类型：**

Render Graph 渲染节点专用的数据载体类（Data Carrier Class）。

**一句话职责：**

作为数据“信使”，负责把主线程“录制阶段（Record）”获取的纹理句柄、材质和参数，安全打包传递给后续“执行阶段（Execute）”的渲染回调函数。

**所在模块：**

通常以 `private class PassData` 的形式嵌套声明在具体的 `ScriptableRenderPass`（如 `BloomRenderPass`）内部。

**它管理什么数据：**

- `TextureHandle src`：Blit 输入源纹理句柄。
- `TextureHandle dst`：渲染写入目标纹理句柄。
- `Material blitMaterial`：执行渲染时调用的材质引用。
- `int passIndex`：材质中指定执行的 Shader Pass 索引。

**它被谁创建：**

由 Render Graph 在调用 `renderGraph.AddRasterRenderPass<PassData>(...)` 时通过泛型在底层自动实例化并作为 `out passData` 返回。

**它被谁调用：**

- 写入：在 `RecordRenderGraph()` 录制阶段由开发者填充字段。
- 读取：在 `SetRenderFunc(static (PassData data, RasterGraphContext context) => ...)` 的执行回调中读取字段。

**关键方法：**

无关键方法，纯粹作为强类型数据结构使用。

**输入：**

- `RecordRenderGraph` 阶段获取的 `TextureHandle`、`Material` 等。

**输出 / 影响：**

- 为执行阶段提供执行 `Blitter.BlitTexture` 所需的全部参数。

**和其他类的关系：**

- `ScriptableRenderPass`：包含并声明它的结构。
- `IRasterRenderGraphBuilder`：通过 `AddRasterRenderPass<PassData>` 关联此数据类型。
- `Blitter`：在执行函数中使用 `PassData` 的数据发起绘制指令。

**是否需要深挖：**

现阶段重点掌握：
- 它是 Render Graph 分离“录制与执行”架构的核心桥梁。
- 配合 `static` Lambda 使用时，所有执行所需的外部状态都必须存入 `PassData` 传过去，禁止在 Lambda 内部直接抓取外部成员（避免闭包与 GC）。

暂时不用深挖：
- Render Graph 底层针对 PassData 的对象池（Object Pool）复用与生命周期回收机制。
